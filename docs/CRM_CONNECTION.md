# Подключение планировщика к Railway

Подготовлено 5 сентября 2026. Этот документ описывает код подключения; наличие кода не означает, что production уже настроен.

## Порядок активации

1. Опубликовать совместимую версию CRM с `/api/webhooks/ad-order`, `/api/webhooks/content` и `/api/reminders/due`.
2. Слить PR этой задачи и развернуть Railway. Существующие Mollie, Telegram и Google Calendar остаются в Railway.
3. В Variables сервиса Railway задать:

| Переменная | Значение |
|---|---|
| `CRM_AD_ORDER_URL` | `https://alex-planner.alex-podslushano.chatgpt.site/api/webhooks/ad-order` |
| `CRM_WEBHOOK_SECRET` | Тот же секрет, что в настройках Site. Текущее значение скрыто, поэтому при отсутствии сохранённого ключа требуется согласованная ротация на обеих сторонах. |
| `CRM_SITES_AUTH_TOKEN` | Серверный токен доступа к закрытому Site, полученный через Sites; без префикса Bearer. Не использовать временную учётную запись Git. |
| `CRM_TELEGRAM_CHAT_ID` | Рабочий чат Алекса, куда должен писать существующий бот. |

Секреты не вставлять в GitHub, браузерный JavaScript или публичные сценарии. CRM остаётся закрытой.

## Поведение после активации

- Новая рекламная бронь и изменение оплаты запускают синхронизацию.
- Каждые 5 минут сверяются сохранённые брони; неуспешные передачи повторяются, неизменённые записи пропускаются.
- Первое подключение импортирует существующие рекламные брони, кроме ручных закрытий дат. Исторические оплаты проверяются через Mollie, дата дохода берётся из paidAt. Неизвестная дата или недоступный Mollie откладывают импорт до следующей попытки.
- CRM использует постоянный ID заявки и ID платежа, чтобы не удваивать карточки и доходы. Рабочие заметки сохраняются при повторной синхронизации.
- Сводка задач, публикаций и рекламы на сегодня/завтра готовится после 08:30 Europe/Amsterdam с шагом проверки 5 минут. Повторный контакт включён в сводку. Прошедшие даты не отправляются.
- Доставка отмечается в базе Railway после успешной отправки. В редком случае остановки процесса между отправкой и отметкой возможно повторное сообщение; абсолютная exactly-once доставка не гарантируется. При нескольких репликах потребуется распределённая блокировка. Начальный запуск: одна реплика.
- Сообщения об оплатах уже отправляет существующий обработчик бота. Эта интеграция не дублирует их. Отдельные немедленные Telegram-уведомления о неоплаченной заявке ещё не добавлены.

## Make

Добавить HTTP POST после планирования/публикации, URL:
`https://alex-planner.alex-podslushano.chatgpt.site/api/webhooks/content`

Заголовки: `Content-Type: application/json`, `x-crm-webhook-secret: <секрет>`, `OAI-Sites-Authorization: Bearer <серверный токен Sites>`.

```json
{"external_id":"stable-scenario-record-id","title":"Название публикации","project":"podslushano.nl","channel":"Instagram","format":"Пост","status":"Опубликовано","publish_date":"2026-09-05"}
```

Допустимые статусы: Идея, В работе, Запланировано, Опубликовано. При изменении статуса нужно передавать тот же external_id. Один и тот же идентификатор нельзя использовать для разных публикаций. Make пока не настроен и не проверен на реальном сценарии.

## Проверка запуска

- Убедиться, что запрос с двумя заголовками доходит до CRM, а запрос без защитного ключа отклоняется.
- Передать тестовую неоплаченную заявку; проверить клиента, сумму, дату и ID.
- Повторить заявку; количество карточек должно остаться прежним.
- Провести тестовый платёж Mollie в тестовом режиме; проверить одну запись дохода и дату из paidAt. Не инициировать платёж с реальными деньгами ради диагностики.
- Убедиться в доставке одной тестовой сводки в согласованный Telegram-чат и проверить повторную попытку.
- Проверить в Make один полный цикл публикации и обновление той же карточки.
- Сверить импортированные реальные брони и старые стартовые записи CRM. Стартовые рекламные и финансовые записи не удалены автоматически.

## Что остаётся за пределами этого подключения

Чтение входящей почты, автоматическое сопоставление материалов из писем, управление через ChatGPT/MCP, полноценные возвраты/chargeback и хранение отдельных выходов многодатной кампании в CRM. Сейчас CRM показывает первую дату кампании; полный набор дат остаётся в Railway/Google Calendar и в исходном комментарии заявки. Эти возможности нельзя считать готовыми.
