# Allo Walks: страница без плагинов WordPress

## Что уже реализовано

- `static/allo-walks/wordpress-embed.html` — один блок HTML/CSS/JS для страницы WordPress. Для просмотра без WordPress тот же код отдаётся по `/allo-walks/v2`.
- Каталог и остатки мест приходят с существующего сервиса `worker` на Railway. Браузер не задаёт итоговую цену.
- Оформление прогулки и сертификата создаёт платёж через имеющееся подключение Mollie; webhook и возврат со страницы оплаты проверяют статус платежа через Mollie API.
- Оплаченные места и неоплаченные брони на 60 минут учитываются в базе. Повторный webhook не выпускает второй сертификат.
- Код прежнего абонемента можно применить к прогулке категории `city` или `nature` с адреса владельца. Код сертификата покрывает сумму полностью или частично, остаток сохраняется.
- После подтверждения оплаты письмо уходит участнику или получателю сертификата через существующий почтовый канал проекта. Фоновая сверка раз в минуту перепроверяет неразобранные платежи Mollie и повторяет отправку письма при сбое.

## До публикации продаж

1. Заполнить `content/allo_events.json` **только подтверждёнными** прогулками. Сейчас массив пуст. Не стоит публиковать вымышленные даты или цены.
2. Заполнить `gift_amounts_eur` в `content/allo_settings.json` согласованными номиналами. Сейчас список пуст, поэтому покупка сертификатов скрыта.
3. Проверить, что у каждой прогулки есть 3–6 **разных реальных** фото с правами на публикацию и работающими HTTPS-ссылками. На странице все фотографии берутся из каталога, никаких сгенерированных изображений код не добавляет.
4. Подтвердить точное место и время встречи, последовательность маршрута, включения/исключения, вместимость, цену и правила отмены. Нужны отдельные условия для прогулок и сертификатов; существующая общая страница `/terms` описывает другой сервис и здесь не подставлена. До продаж дополнить страницу конфиденциальности данными о покупателях и получателях подарков.
5. Задать `ALLO_PAGE_URL` в Railway как полный URL опубликованной страницы WordPress. Иначе после Mollie покупатель вернётся на резервную страницу `/allo-walks/v2`.
6. Проверить `WP_URL` или `SITE_URL` в Railway: origin WordPress должен совпадать для CORS. Ключ `MOLLIE_API_KEY`, `WEBHOOK_BASE_URL`, почтовые настройки и постоянный том `/app/data` уже принадлежат существующему сервису.
7. Задать постоянный `ALLO_CODE_ENCRYPTION_KEY` в Railway. При отсутствии отдельного ключа используется существующий `GMAIL_TOKEN_ENCRYPTION_KEY`. Ключ нельзя менять без переноса зашифрованных кодов.
8. Провести тестовую покупку прогулки и сертификата с тестовым ключом Mollie, проверить webhook, изменение остатка мест и письмо получателю. Затем проверить live-ключом на минимальной согласованной сумме.

## Формат подтверждённой прогулки

Каждый объект массива `content/allo_events.json`:

```json
{
  "key": "unique-slug-2026-11-21",
  "status": "published",
  "category": "city",
  "title": "Подтверждённое название",
  "place": "Город",
  "starts_at": "2026-11-21T11:00:00+01:00",
  "meeting": "Точный адрес или выход станции",
  "duration": "11:00–16:00",
  "intro": "Короткое описание дня",
  "route": ["Первая точка", "Вторая точка"],
  "included": ["Подтверждённое включение"],
  "extra": ["Расход отдельно"],
  "price_cents": 4900,
  "capacity": 8,
  "photos": [
    {"url": "https://example.com/real-photo-1.jpg", "alt": "Описание фото"},
    {"url": "https://example.com/real-photo-2.jpg", "alt": "Описание фото"},
    {"url": "https://example.com/real-photo-3.jpg", "alt": "Описание фото"}
  ]
}
```

Пример показывает **структуру**, а не событие для публикации. Допустимые категории: `city`, `nature`, `special`. У старого абонемента действует ограничение только на первые две категории. Событие появляется в каталоге лишь при статусе `published`, будущей дате, полной информации и 3–6 разных фото. Для черновика используйте `"status": "draft"`.

Новая витрина допускает максимум 8 продаваемых мест для гостей на событие. Организатор и приглашённые специалисты в эти 8 мест не входят. Для них нужно отдельно согласовать места и расходы с партнёрами.

## Старые абонементы

Сначала вручную проверить владельцев и оставшиеся прогулки. Создать локальный CSV с колонками `email,remaining_uses`, где число от 1 до 3. Затем в окружении с доступом к производственной базе выполнить:

```bash
python -m scripts.allo_import_passes --input /secure/passes.csv --output /secure/issued-codes.csv
```

Выходной файл содержит действующие коды; его нельзя добавлять в git или публиковать. Владельцам нужно доставить код приватно. Один адрес не импортируется дважды без ручной проверки.

## Рабочие ограничения

- Код сам по себе не может обещать гарантию работоспособности на два года: её дают договорённость о сопровождении, мониторинг, резервные копии базы и контроль изменений Mollie/WordPress/Railway. Эти процессы нужно согласовать отдельно.
- Если платёж подтвердится после 60 минут и место уже занято, заказ перейдёт в `refund_requested`; его нужно проверить и вернуть деньги. Состояние видно в базе и журнале Railway.
- Для помещения скрипта в HTML-блок WordPress нужен доступ, при котором WordPress не удаляет тег `<script>`. Скопируйте весь файл как один блок «Произвольный HTML», затем проверьте страницу после сохранения.
