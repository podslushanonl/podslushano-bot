# Правила качества приложения

Чек-лист, по которому проверяем экраны перед выпуском. Составлен по открытым руководствам
React Native / Expo (Vercel «react-native-skills», MIT) и методике аудита интерфейса из каталога
kursku/skills (только как справка, файлы каталога в репозиторий не копируются).

## Производительность
- Длинные списки не рисуются целиком: показываем порцию (30) и «Показать ещё» или FlatList.
- Фильтры и группировки списков — в `useMemo`, чтобы не пересчитывать при каждой перерисовке.
- `Intl.DateTimeFormat` и другие форматтеры создаются один раз на уровне модуля, не в каждой строке.
- Анимируем только `transform` и `opacity` (Reanimated), не ширину, высоту и отступы.
- Картинки — только `expo-image` (`Img` из `@/ui`), с подложкой, пока грузится.

## Нажатия и доступность
- Зона нажатия не меньше 44×44: у маленьких кнопок `IconButton` добавляет `hitSlop` сам.
- У каждой кнопки без текста — `accessibilityLabel` по-русски; у заголовков — `accessibilityRole="header"`.
- Контраст текста не ниже 4,5:1 в светлой и тёмной теме (цвета только из токенов `@/theme`).
- В JSX нет `{число && …}`: только явные условия (`n > 0 ? … : null`), иначе на экран попадёт «0».

## Тексты и состояния
- Каждый экран с загрузкой показывает скелетон, ошибку с кнопкой «Повторить» и пустое состояние
  с понятным следующим шагом — не «ничего нет».
- Ошибки — что случилось и что сделать («Проверьте интернет и попробуйте ещё раз»).
- Бренд пишется строчными: podslushano.nl. Без эмодзи в интерфейсе — только иконки. Не писать «NL».
